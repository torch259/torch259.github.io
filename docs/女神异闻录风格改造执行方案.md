## 一页速览（写给忙人）

| 项目 | 内容 |
|---|---|
| 一句话方案 | 先把 P5 视觉语言固化成一份 `DESIGN_SPEC.md`（风格唯一权威），再按「素材清单 MANIFEST → 分批生成素材 → 前端分层落地 → 截图评审循环」由 Agent 流水线执行 |
| 素材原则 | **绝不直接搬运/截图 ATLUS 官方美术资源**；风格致敬用"原创生成 + 程序化纹理(SVG/CSS)"实现 |
| 素材利用层级 | ① 你已有素材（照片/头像/自绘）做"原料" → ② AI 生成原创 P5 风素材 → ③ SVG/CSS 程序化纹理（噪点、斜线、切角、放射线）零图片成本 |
| 推荐改造幅度 | 三个档位，建议从「B 档」开始，达成后再决定是否冲 C 档（见下） |
| 预计工作量 | A 档半天 / B 档 1–2 天 / C 档 2–4 天（AI 生成等待 + 评审循环占大头） |
| 人只做三件事 | ① 定风格方向并批准 SPEC；② 素材版权/审美 gate；③ 最终验收拍板 |

**三档目标（任选，范围决定素材量与工时）：**

- **A 档 · 轻量换肤（纯 CSS 变量）**：只改 `:root` 设计令牌 + 少量组件细节。零新增图片素材。效果：黑底红白高对比，气质已变，但仍是"现代卡片风"。
- **B 档 · 中量重构（推荐）**：A 档 + 切角/斜切面板、双线描边、字体替换、噪点纹理、主视觉 Hero 图 1–2 张、按钮/导航重绘。需素材：1 张 hero + 程序化纹理 + 1 套字体文件。
- **C 档 · 深度还原**：B 档 + 每视图独立主视觉/插画、切角插画卡、日历"怪盗日程"样式、播放器全定制 UI、入场/切场动画、音效位。素材最多，评审循环最长。

> 本项目的时钟 + 月历组件与 P5「日期推进」叙事天然契合，是**性价比最高的重点改造区**，建议 B 档起就优先做。

## 红线与版权说明（先读）

1. **不要**：把 P5 游戏截图、官方 UI 贴图、角色立绘、官网素材、商标 Logo（含怪盗团面具标志）放进站点。
2. **可以**：致敬其**视觉语言**（黑白红高对比、斜切面板、全大写宽字距、噪点拼贴、放射线、对话框卡角），用自己的原创素材实现。
3. 本改造若仅本地/个人使用风险很低；若公开部署，坚持"原创生成"，并在页面页脚留一行 `视觉灵感：Persona 5（仅风格致敬，素材均为原创/AI 生成）`。
4. AI 文生图工具（Midjourney / DALL·E / Flux / SD 系）**不要在其提示词里要求复刻角色名**（如 "Joker"、"Ann"），用风格描述词（如 "phantom thief, noir, high-contrast red black white, anime game UI"）生成原创形象。
5. 字体优先选 **OFL 开源协议**并自托管（静态站无 CDN 依赖、离线可用），禁止直接嵌入盗版字库。

## 第 0 步：现有素材盘点（现状审计）

> 审计结论（2025 年已核对）：当前仓库 **没有任何图片/音频素材**，样式 100% 由 `css/style.css` 顶部的 CSS 变量驱动 → 好处是**换肤成本极低**，坏处是一切图片类资产都要新建。

### 0.1 清点"现有美术素材"（你手上可能有的原料）

| 原料类别 | 来源 | 用途示例 | 是否需要版权确认 |
|---|---|---|---|
| 个人照片 / 头像 | 手机、网盘 | 头像 → 转"怪盗剪影/硬边头像" | 自有，无版权问题 |
| 自绘/约稿插画 | 本地、PSD | Hero 主视觉原料 | 看约稿协议（个人用途一般 OK） |
| AI 生成图 | 之前生成的原图 | 二次处理原料 | 按所用工具条款（个人用途基本 OK） |
| 截图/网图 | ⚠️ 一般不行 | 只能做"参考板"（moodboard），不进站点 | 需逐一确认授权 |

做法：在仓库外建一个 `素材收集/` 临时夹（**不入 git**），Agent 盘点时只读、不搬运；确认能用的原料再拷入 `assets/originals/`（见第 3 步）。

### 0.2 页面结构审计（Agent 改造前必须掌握的 DOM 事实）

当前 5 个视图由 `js/router.js` 按 hash 切换，DOM 约定已被 JS 依赖，**改造尽量不动 HTML 结构、不碰 JS**：

| 视图 | 关键挂点（id / class） | 现有视觉 |
|---|---|---|
| 顶栏 | `.site-header` `.brand` `.nav a`（active 用渐变药丸） | 毛玻璃 + 圆角药丸 |
| 首页 | `#avatar` `#nickname` `#motto` `#intro`；`#clock` `.clock-widget`；`#calendar` `.calendar-widget`；`#quick-links` `.ql` 卡片 | 渐变头像、渐变时钟卡、矩阵日历、白卡片 |
| 关于 | `.about-card` `#hobbies` `.hobby` 标签 | 白卡片、圆角标签 |
| 作品 | `#repos` `.repo` 卡片（GitHub API 动态渲染） | 白卡片 |
| 音乐 | `.player` `.cover` `.ctrl` `.progress` `#playlist` `.song` | 圆按钮、圆滑条 |
| 小工具 | `#feature-list` `.feature` 卡片 | 白卡片 |
| 页脚 | `.site-footer` | 细线分隔 |

> 全部组件底色/圆角/阴影由 `--bg --card --radius --accent --grad --border` 等十几个 CSS 变量控制 → **变量表就是换肤总开关**（第 7 步给了映射）。

## 第 1 步：风格拆解 —— 什么是"P5 味"

> 用途：这一步产出 `docs/DESIGN_SPEC.md`，是所有素材/代码 Agent 的**唯一风格权威**。Agent 上下文彼此不共享，**一切靠这份文件传话**。

### 1.1 可操作拆解（评审时逐条打钩）

| 维度 | P5 风格特征（可操作描述，供 Agent/提示词使用） |
|---|---|
| 色彩 | 近黑底、纯白、正红 `#E60012` 系强调；少量灰阶；避免大面积渐变/柔光 |
| 形状语言 | 面板大量**斜切/平行四边形切角**（clip-path）、细**双线描边**、尖角代替圆角；装饰用三角/菱形/放射线/斜条纹 |
| 字体 | 英文/数字用几何粗体大写 + **宽字距**；中文标题用超粗黑体；正文保持可读黑体白字 |
| 排版 | 标题巨大、挤边、顶格；标签式小字（如日期/序号）；信息卡片像"游戏菜单条目" |
| 纹理 | 全局轻微噪点/网点（halftone）、撕裂拼贴边、屏幕扫描线可选 |
| 动效 | 快、硬、干脆（150–250ms ease-out）；切视图可闪白/闪红一帧；hover 用位移+色块而不是柔光 |
| 时钟/日历 | 大号等宽数字（tabular-nums）；日期可做成"行动日程/倒计时"样式 —— 本页最强卖点 |

### 1.2 `DESIGN_SPEC.md` 应有骨架（Phase 1 的产出物）

```markdown
# DESIGN_SPEC — P5 致敬风
## 1. 风格宣言（一段话，所有 agent 都要读）
## 2. 色板（十六进制 + 用法 + 禁止用法）
## 3. 字体（标题/正文/数字各自的 family、自托管文件名、回退栈）
## 4. 组件图样（导航/卡片/按钮/时钟/日历/播放器逐条：形状、描边、切角角度、hover 行为）
## 5. 素材清单（引用 assets/MANIFEST.md 的 ID，规定每张图怎么用、放哪）
## 6. 动效规则（时长/缓动/哪些元素允许动画）
## 7. 反例区（出现即判不合格：圆角药丸、大渐变、玻璃拟态、emoji 当图标…）
```

## 第 2 步：素材 → 页面挂点映射表（素材利用的核心）

> 铁律：**先定挂点，再生产素材**。每张图必须知道"挂到哪个元素、什么尺寸、什么状态"，否则就是无效素材。

| 素材 ID | 用途（挂点） | 呈现方式 | 规格建议 | 生产方式 |
|---|---|---|---|---|
| `IMG-HERO` | 首页 Hero 主视觉（`#view-home` 背景 or `.hero` 侧图） | WebP，`<img>` 或 `body::before` 固定层 | 16:9 / 1:1，宽 ≥1600px，≤400KB | AI 文生图 → 放大 → 抠图/压边 |
| `IMG-AVATAR` | 头像（`#avatar`，JS 支持 `<img>`） | 硬边/切角怪盗风头像 | 512×512 方图 ≤200KB | 你的照片 → AI 风格化 / 纯 AI |
| `UI-FRAME` | 卡片切角描边（`.card .ql .repo .feature` 通用） | **SVG/CSS clip-path 实现，非图片** | 原子化，可复用 | Agent 手写 SVG/CSS（推荐） |
| `TX-NOISE` | 全局噪点（`body::after` 全屏叠加） | SVG data-URI 或 256px 灰噪 PNG ≤10KB | 平铺 | 程序化生成 |
| `TX-HALFTONE` | 色块/按钮内网点渐变（hover、播放键） | SVG data-URI | 原子化 | 程序化生成 |
| `TX-STRIKE` | 斜条纹强调条（分隔线、标签底） | SVG data-URI | 原子化 | 程序化生成 |
| `IMG-WORKS` | 作品卡小图标/占位（`.repo`） | 可不做，用 UI 符号 | — | CSS 符号即可 |
| `IMG-COVER` | 播放器封面占位（`#cover`，无歌时） | 一张红色网点方图 | 256×256 ≤30KB | 程序化/文生图 |
| `FNT-DISPLAY` | 标题/数字字体 | woff2 自托管 | 每 weight ≤200KB（子集化） | 下载 OFL 字体 → 子集化 |
| `IMG-POSTER-x`（C 档） | 关于/音乐/作品每视图角落插画 | WebP | ≤300KB/张 | AI 文生图 |
| `SFX-*`（可选 C 档） | 按钮/切换音 | ogg/mp3 短音 | ≤100KB/个 | 合成/开源音效库 |

> 挂点明细 = 第 0.2 节表格 × 上面每行素材，落进 `MANIFEST.md` 的"挂点"列。

## 第 3 步：素材目录、命名与清单（MANIFEST）规范

### 3.1 目标目录结构（本方案落地时由 Agent 自动创建）

```text
assets/
├── originals/        # 你的原料（照片/原画），不进构建体积
├── bg/               # 大背景/主视觉       命名：<用途>-<主题>.webp
├── ui/               # UI 装饰位图（极少，优先 SVG）
├── textures/         # 噪点/网点/条纹     命名：<类型>-<颜色>.svg|png
├── fonts/            # 自托管字体 woff2
└── MANIFEST.md       # ★ 素材清单（唯一登记表，Agent 每次增删都更新它）
```

### 3.2 命名规范

- 全小写连字符：`hero-mask-red.webp`、`noise-dark.svg`、`font-display-latin.woff2`
- 不用中文文件名（避免静态服务器/缓存问题），说明写进 MANIFEST
- 每张图一行记录，字段固定，Agent 与人都靠它核对：

### 3.3 `MANIFEST.md` 表格模板

```markdown
| ID | 文件 | 挂点 | 尺寸 | 格式 | ≤大小 | 状态 | 提示词存档 | 版权备注 |
|---|---|---|---|---|---|---|---|---|
| IMG-HERO | assets/bg/hero-main.webp | #view-home | 1600×900 | webp | 400KB | 待生成 | prompts/hero.md | 原创 AI |
| IMG-AVATAR | assets/bg/avatar-me.webp | #avatar | 512×512 | webp | 200KB | 待生成 | prompts/avatar.md | 本人照片改 |
| TX-NOISE | assets/textures/noise-dark.svg | body::after | 矢量 | svg | 3KB | 待生成 | — | 程序化 |
…
状态流转：待生成 → 已生成 → 已审核 → 已挂接 → 已废弃(注明原因)
```

> 提示词正文一律存档在 `prompts/<ID>.md`，保证素材**可复现、可回炉**。

## 第 4 步：Agent 团队怎么搭（角色卡）

> 核心思想：**文件即记忆，文档即契约**。给每个 Agent 独立上下文不可靠，但 `DESIGN_SPEC.md`、`MANIFEST.md`、阶段报告文件是共享的、可审计的。

### 角色卡总览

| 角色 | 职责 | 主要产出 | 触发方式 |
|---|---|---|---|
| **美术指导（Art Director）** | 写死风格规范；裁决审美争议 | `docs/DESIGN_SPEC.md` | 每阶段开始前复述/微调 |
| **素材生产者 × N（并行）** | 按 MANIFEST 未完成项生成素材；更新 MANIFEST | `assets/**` + `prompts/**.md` | 一次派多个，互不依赖 |
| **前端实现（Frontend）** | 按 SPEC 分层改 CSS/HTML；本地起服务自测 | 代码 diff + 阶段报告 | 每次只改一个批次，改完报告 |
| **视觉评审（QA）** | 起预览 → 逐视图截图 → 按验收清单打分 | `docs/review-<轮次>.md` | 每轮收尾自动触发 |
| **人（你）** | 批准 SPEC / 素材 gate / 最终拍板 | 决策记录 | 每个 gate 手动放行 |

### 分工原则

1. **素材生产**永远并行（互不读对方文件，只写自己那份 MANIFEST 行，最后合并冲突由人在 gate 处理或串行更新）。
2. **前端实现**与**素材生产**可并行一小段：素材未就绪时前端先把占位色块/程序化纹理搭好（正好 B 档就是这个顺序）。
3. **评审 Agent 的截图就是证据**：报告里贴 `docs/shots/*.png`（每视图一张），人不用开浏览器也能审。
4. 单 Agent 全程跑也行（省钱省配置），但**必须分阶段停**，防止上下文被污染、风格漂移。

## 第 5 步：分阶段执行流程（Phase 0–6）

> 每个 Phase 有：**目标 / 谁来做 / 输入 / 任务 / 产出 / 验收（gate）**。gate 不过不进入下一阶段。

### Phase 0 · 基线快照与分支
- **人 + 本地 Agent**：`git checkout -b persona-style`；起本地预览（`python -m http.server 8000` 或 `npx serve .`）逐视图截图存 `docs/baseline/`（改造前后对比用）。
- **产出**：基线截图、当前 `:root` 变量表备份。
- **Gate**：5 个视图 + 移动端宽度都能正常显示（无素材也成立）。

### Phase 1 · 风格固话（写 DESIGN_SPEC）
- **美术指导 Agent**（可让人工给方向词，如"黑红高对比、怪盗、杂志拼贴"）+ 第 1 节骨架 → `docs/DESIGN_SPEC.md`。
- 同时**盘点 Agent** 产出第 0 步盘点表、确定素材缺口 → `assets/MANIFEST.md` 初版（全"待生成"）。
- **Gate（人）**：SPEC 你看得懂、认同；素材清单里没有红线圈内的项目。

### Phase 2 · 素材生产（并行批次）
- **素材 Agent × N**：按第 6 节 prompt 模板批量生成。批次建议：
  - Batch-A（程序化，最稳）：TX-NOISE / TX-HALFTONE / TX-STRIKE / UI-FRAME / IMG-COVER —— 几乎零失败率；
  - Batch-B（文生图）：IMG-HERO、IMG-AVATAR（用你的照片做原料时优先风格化而非凭空生成）；
  - Batch-C（字体）：下载 OFL 字体、子集化、登记回退栈。
- **Gate（人）**：逐张看 → 不合格让 Agent 重生成（限 3 轮）；改 MANIFEST 状态为"已审核"。
- 产出物一并入 `prompts/`。

### Phase 3 · 前端第一轮：令牌换肤（不动 HTML/JS）
- **前端 Agent**：按第 7 节把 `:root` 换成 P5 令牌 → 全局立刻变黑红白；修被变量牵连的细节（渐变药丸导航、白色 hover 底色等）。
- **验收**：截图对比 baseline，5 视图无布局崩坏、文字可读。
- **Gate（人）**：可进 B 档继续。

### Phase 4 · 组件与素材挂接（分视图推进，顺序重要）
按依赖排序逐批让前端 Agent 完成并自测：
1. 全局层：噪点叠加、字体、导航切角样式、通用卡片切角双线；
2. 首页（优先）：Hero 主视觉 + 时钟"大数字日程卡" + 日历矩阵化；
3. 关于/作品/小工具：卡片族复用；
4. 音乐播放器（改动最多的自研组件）：按钮/滑条/歌单条目/封面占位；
5. 页脚 + 空状态。
- 每批改完 → 本地起服务截图 → 贴入该批报告。
- **Gate（人）**：视觉抽检通过。

### Phase 5 · 视觉评审循环（QA Agent × 人）
- **评审 Agent**：按第 8 节清单给每个视图打分（0–5），列问题 + 截图定位，输出 `docs/review-<轮次>.md`。
- **前端 Agent** 修 → 复评。**上限 3 轮**，超限回到人裁决（砍需求 or 接受）。
- **Gate（人）**：均分 ≥4 且无 P0/P1 项 → 通过。

### Phase 6 · 收尾与交付
- 性能审计（每图 ≤ 预算、开启懒加载 `loading="lazy"` 给非首屏图）、字体子集核对、无障碍抽查（对比度/可点区域）、移动端 880/600px 两档复核；
- 清理 `prompts` 外临时文件、更新 README 说明"如何替换素材/切回旧皮肤（A 档变量注释保留）"；
- `git add -A && git commit`（分 2–3 个语义化 commit）；可选推送 Pages 预览分支给人点开验收。

### 7.7 字体自托管（assets/fonts/）

```css
@font-face {
  font-family: "P5Display"; font-weight: 900; font-display: swap;
  src: url("../assets/fonts/display-latin.woff2") format("woff2");

}
```

## 第 8 步：验收检查清单（评审 Agent 打分表）

> 每视图打 0–5 分；P0=功能/可读性崩坏，P1=明显视觉违和，P2=细节打磨。任何 P0 一票否决。

**风格一致性（每视图）**
- [ ] 色彩符合 SPEC 色板，无残留浅色拟态元素（圆角药丸、大渐变、毛玻璃大卡）
- [ ] 卡片/按钮/导航形状统一（切角 or 双线，全站一致）
- [ ] 字体族与字距符合 SPEC；中文无乱码、无字体回退突兀
- [ ] 装饰（噪点/斜线/网点）不过量，不干扰正文阅读

**功能回归（每视图）**
- [ ] 5 个视图切换、hash 直链可刷新
- [ ] 时钟每秒刷新、日历翻月/回今/点选正常（改造不碰 JS 时本应自动通过）
- [ ] 播放器播放/切歌/折叠歌单/音量正常；空状态样式正常
- [ ] 作品库加载失败时的占位与空状态可读

**技术**
- [ ] 每图 ≤ MANIFEST 预算；非首屏图 `loading="lazy"`
- [ ] 桌面（≥1280）/平板（880）/手机（≤600）三档无横向滚动、切角不吞字
- [ ] 文字与背景对比度达标（正文 ≥ 4.5:1，大字 ≥ 3:1）
- [ ] 无 `console` 报错；无外链字体/Font 闪烁（FOUT）可接受但要在 `font-display: swap`

## 风险、回滚与注意事项

| 风险 | 概率 | 缓解 |
|---|---|---|
| 风格漂移（不同 Agent 各改各的） | 中 | 一切以 `DESIGN_SPEC.md` 为唯一契约；每批报告附"与 SPEC 差异自检" |
| AI 文生图出图不达预期、反复烧钱 | 高 | 程序化素材先行；文生图限定 3 轮重试；先小图试错再出大图 |
| 版权/商标风险 | 低→中 | 只做风格致敬；素材清单强制"版权备注"列 |
| 改动 JS/HTML 引发功能回归 | 低 | 铁律：JS 零改动；HTML 只加不加删；每批截图回归 |
| 切角 clip-path 裁剪内容/圆角冲突 | 中 | 卡片 padding 加大；`::before` 手绘框；移动端逐档看 |
| 中文字体过大拖慢加载 | 中 | 子集化 + `unicode-range` + `font-display: swap` |
| **回滚** | — | 每个 Phase 一个 commit；Phase 0 分支 `persona-style`，随时 `git revert` 或切回 `main`；`:root` 旧变量保留为注释可一键回 A 档 |

## 如何在这个环境（DSH/多 Agent）里真正跑起来

以本仓库为例的最小跑法（把本文档作为项目里的"总任务书"喂给执行 Agent）：

1. **Phase 0**：`git checkout -b persona-style`；`python -m http.server 8000` 起本地服务；让一个 Agent 逐个打开 5 个 hash 视图并截图存 `docs/baseline/`。
2. **Phase 1**：派「美术指导」Agent：给它第 1.2 节骨架 + 你的方向话（如"黑红高对比、怪盗、日程日历优先"）→ 产出 `docs/DESIGN_SPEC.md` 与 `assets/MANIFEST.md` 初版；你审。
3. **Phase 2**：把 MANIFEST 里"待生成"拆成 Batch，同时派多个「素材」Agent（每个只负责自己的 ID 列表）→ 产出到 `assets/`，写回 MANIFEST 状态；你逐张过 gate。
4. **Phase 3–4**：派「前端」Agent：指令 = "只改 css/style.css，读 DESIGN_SPEC 第 4 节 + 7 节手册，先令牌后组件，每批起服务截图报告"。
5. **Phase 5**：派「评审」Agent：给第 8 节清单 → 输出 `docs/review-1.md`（含截图路径与分数）→ 不合格把问题文件转给前端 Agent 修，最多 3 轮。
6. **Phase 6**：你 final walkthrough 后合入。

**关键经验**：
- Agent 之间**永远不靠对话传话**，只靠仓库里的 SPEC/MANIFEST/截图/报告文件；
- 一个阶段一个 commit，失败只回滚一个 commit；
- 人审素材时把"审美结论"写回 SPEC 的"反例区"，避免同类问题反复出现。
